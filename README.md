# Карточка клиента: генератор csv и конвертер csv → XML

Приложение без зависимостей и без сервера. Откройте `dist/index.html` (один файл, можно переслать)
или `index.html` в корне двойным щелчком.

- **Генератор csv** — тестовая выгрузка PRSN, BUSN или LEGL с любым числом строк. Контрольные суммы
  ИНН, ОГРН, ОГРНИП, СНИЛС, ОКПО и счетов верны, паспорт, адрес и даты согласованы. Флажок «грязные
  данные» добавляет то, что встречается в жизни: счета после Excel, потерянные нули, адреса строкой.
- **Конвертер** — csv → по одному XML на клиента, проверка по XSD, дерево всей схемы со значениями
  и источником каждого значения, выгрузка XML, zip и отчёта.

## Как устроен код

Обычные скрипты с общим пространством имён `Comita` (ES-модули не работают при открытии файла
с диска). Порядок слоёв задаёт только `index.html`; слой зависит лишь от слоёв выше по списку.

| Слой | Папка | Что внутри |
|---|---|---|
| core | `src/core` | csv, xml, модель XSD, валидатор XSD, контрольные суммы, случайные числа, zip. Ничего не знает о карточке клиента |
| model | `src/model` | `input/` — колонки csv с алиасами; `output/` — алиасы полей XML; `dict/` — справочники |
| mapping | `src/mapping` | `*.map.js` — правила «поле ← колонка», по одному на строку; `defaults.js` — умолчания; `transforms.js` — преобразования; `engine.js`, `builder.js` — исполнение |
| generator | `src/generator` | `entities.js` — клиент и его части; `*.gen.js` — «колонка ← значение клиента»; `dirty.js` — порча данных |
| services | `src/services` | `load` (загрузка), `convert` (применение маппинга), `schema` (проверка по XSD), `export` (выгрузка), `generate` |
| ui | `src/ui` | вкладки и отрисовка; только здесь есть работа с DOM |

Что где менять:

- изменилась выгрузка csv — `src/model/input/*.js` (колонки идут по порядку);
- поле XML надо брать из другой колонки — одна строка в `src/mapping/*.map.js`;
- другое значение по умолчанию — `src/mapping/defaults.js`;
- новое соответствие «текст → код» — `src/model/dict/codes.js`;
- изменилась схема — заменить файлы в `schemas/` и выполнить `node build.js`. Алиасы и маппинг
  сверяются со схемой при запуске: ошибка назовёт поле, которого больше нет.

## Команды (нужен Node.js 20+, только для разработки)

    node build.js        # пересобрать schemas/clientinfo.xsd.js и dist/index.html
    node --test          # тесты, включая сверку валидатора с xmllint (если установлен)
    node cli.js generate LEGL 100 --dirty
    node cli.js convert legal_registered_users_profile_info.csv --out xml

## Принятые правила

Расхождения XSD и текстового описания XSD решаются в пользу XSD. Элемент выводится в XML, если у него есть
значение или его требует схема. Поле без источника получает значение по умолчанию с комментарием
в XML. Данные, которым нет места в схеме, попадают в `ИнаяИнф`.
